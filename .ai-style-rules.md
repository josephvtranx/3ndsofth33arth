# AI Style Rules

- Baseline commit: `af96a4c`
- Scan tier: Small (7 handed-off source files; full read)
- Source: Claude design export received 2026-09-16

These rules preserve the visual and structural language of the accepted
frontend handoff while allowing defects and accessibility problems to be fixed.

## Golden Files

- `src/app/page.tsx` — primary visual reference for the portfolio, including
  section rhythm, rail navigation, carousel behavior, lowercase voice,
  grayscale imagery, and responsive composition.
- `src/app/booking/page.tsx` — reference for form layout, compact mono labels,
  gray panel treatments, client-side state, and policy content hierarchy.
- `src/components/Halftone.tsx` — reference for small, typed, reusable visual
  primitives with data supplied through props.
- `src/lib/site.ts` — reference for shared content constants that need one
  obvious editing location.
- `src/app/globals.css` — reference for global color, typography, selection,
  scrolling, and placeholder behavior.

## Naming & State-Control Rules

- Use PascalCase for components and component prop types.
- Use uppercase names for module-level content collections and site constants.
- Keep route-specific state and behavior in its route until reuse is proven.
- Define small route-local helpers above the exported page component.
- Use explicit union types for bounded UI choices such as work and design type.
- Prefer early validation with visible feedback over silent failure.
- Keep decorative elements `aria-hidden` and interaction elements semantic.
- Preserve the visual vocabulary: large whitespace, grayscale imagery,
  halftone fields, a dark left rule, pixel and mono accents, restrained motion,
  and mostly lowercase editorial copy.
- Preserve the content hierarchy and intentional asymmetric composition when
  adapting layouts across breakpoints.
- Prefer Tailwind utilities and existing theme tokens. Add shared CSS only for
  genuinely global behavior or values reused across multiple routes.
- Respect reduced-motion preferences when adding or revising animation.

## DONTs

- Do not replace the design with generic cards, rounded dashboard components,
  gradients, stock imagery, or conventional SaaS styling.
- Do not downgrade Next.js, React, TypeScript, or Tailwind to match the export;
  port the design into the repository's current stack.
- Do not turn static or server-renderable sections into Client Components
  without an interaction requirement.
- Do not use non-semantic elements as buttons or links.
- Do not expose booking records, uploads, credentials, or private environment
  variables in browser code.
- Do not add animation that competes with the artwork or ignores reduced-motion
  settings.
- Do not copy defects from the handoff merely for stylistic consistency.
